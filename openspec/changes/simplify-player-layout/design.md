# Design

## Context

动机和范围见 [proposal.md](proposal.md)。真机截图为 `/tmp/ZenPlayer-player-minimal/iphone-before.png`，iPhone 11、828 × 1792，内容暂停在 21:06。当前 `PlayerView` 把正常状态与自绘播放／停止按钮置于系统播放器之前；`PlaybackQueueControls` 常驻数量、前后按钮和连播开关；`controlPanel` 常驻全部音效选项。本次以布局为边界，不改共享 `PlayerViewModel` 所有权或播放状态机。

## Goals / Non-Goals

**Goals:** 减少常驻层级，让标题、播放器、选集操作在首屏形成清晰顺序；保留可发现的设置及可操作异常。目标行为见 [规格](specs/minimal-player-layout/spec.md)。

**Non-Goals:** 不替换系统播放器，不绘制新音频封面，不复制队列状态或添加网络请求，不关闭原有设备验收缺口。

## Decisions

1. **标题 → 播放器 → 图标操作 → 媒体切换 → 设置。** 沿用浅中性色背景及系统语义前景色，减少彩色胶囊、描边和阴影；标题左对齐、允许多行。保留当前音频 220pt／视频 4:3 承载尺寸，不同时引入比例适配。设计图 `/tmp/ZenPlayer-player-minimal/comparison.png` 左侧是真机截图，右侧是重排合成预览，不是已运行 App。
2. **原生控件承担播放／暂停。** 删除外部重复按钮和正常状态行；更多菜单复用迷你条的停止动作。停止会话包含资源释放，不能用系统暂停代替。原生承载视图身份与 selectedMediaType 的现有行为保持不变。实施核实 `failPlayback` 会释放播放器，失败提示和重试按真实 failed 阶段独立展示；已创建媒体后发生错误也沿用释放后的失败页，不制造持有失败播放器的测试专用状态。缓冲和已播完仍提供简短反馈。
3. **列表图标居中，前后图标分居两侧。** 调整 `PlaybackQueueControls` 的组合接口供播放页注入既有列表按钮，macOS popover 仍锚定该按钮，iOS 仍使用原 sheet。按钮只有图形，保留 L10n accessibilityLabel、既有列表 identifier 和 macOS help。正常完整队列数量只在列表内显示；缺失／部分说明及媒体回退仍在图标行下显示。
4. **媒体选择使用紧凑分段控件。** 绑定仍调用现有异步 `switchMediaType`，保持原有准备期间可用性规则。动态字体下允许控件自然扩展，不硬编码导致文字截断的窄宽度。只用一种弱强调色和选中背景，不再按音视频分成橙／蓝两种颜色。
5. **设置使用页内 DisclosureGroup。** 默认折叠，摘要为当前降噪档位及放大倍数，展开呈现连播及原有音效档位，继续使用现有模型／store 绑定。这样不需要新弹层路由，也绕开已验证的 macOS sheet 自动暂停行为。只增加一个局部展开状态，不添加缓存、定时器或恢复播放逻辑。进度／队列保存错误在折叠区外保留。

   实施采用局部 `DisclosureGroupStyle`，统一整行按钮、右侧展开箭头及读屏展开状态；标识放在按钮而非整个分组，避免 SwiftUI 将分组标识传给子控件。展开内容使用自适应档位网格，普通字体每行五档，大字自动换行。macOS 辅助功能仍可能将该按钮呈现为 disclosure 元素，UI 测试按标识查找，不强绑元素类型。

## Risks / Trade-offs

- [移除自绘按钮后旧 UI 测试找不到播放／暂停] → 受影响用例切换到真实原生控制；若平台识别不同，使用各平台辅助方法，不能加入仅为测试存在的生产按钮。
- [原生错误状态不能发起完整重试] → 失败展示现有 `togglePlayback`／重试路径，覆盖有播放器和无播放器两类失败。
- [额外点击才能调音效] → 设置入口始终可见并显示当前值；播放主流程减少视觉负担。
- [布局重排重建原生播放器] → 先验证原生暂停／继续、设置展开、列表与详情往返时同一会话位置连续；不得以自动 resume 修饰布局副作用。
- [图标辨识、长标题和大字] → 使用标准 SF Symbols，44pt 热区、完整读屏名称，检查窄屏和深色／大字，不删除标题内容换取紧凑。

## Migration Plan

无数据迁移。仅视图、文案及受影响测试调整，可按文件回退；原存储键、队列快照、进度身份和播放服务保持兼容。沿用已有隔离测试入口，不改真机 App 数据来播种测试。本次真机截图只证明当前布局，后续实现的构建、UI 与设备验证分别记录。
