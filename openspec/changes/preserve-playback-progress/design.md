## Context

状态：已批准／验证中；执行证据见 verification.md。动机和现状证据见 [proposal.md](proposal.md)，行为合同见 [playback-progress/spec.md](specs/playback-progress/spec.md)。当前 App target 为 Swift 5、iOS 17／macOS 14，MVVM，UI 状态在主 actor；已加入独立 XCTest target。

规划时基线：`RecentPlaybackStore` 是私有初始化的主 actor 单例，以 `UserDefaults` 的一段 JSON 数组保存最近和进度；`PlayerViewModel` 直接依赖该单例。播放器已有时间观察、恢复 seek 与停止保存，优先围绕这些接口修正。`PlaybackContext` 规划时定义于 `PlayerViewModel.swift`（实施后原样移至 `Models/PlaybackContext.swift`），含单集、原始服务器地址及可选媒体类型，没有系列快照。`RecentPlaybackListView` 直接读取 `records`；下载和历史入口各自创建播放页。

## Goals / Non-Goals

**Goals:** 用少量独立职责完成可测试的长期存储、兼容迁移和最小播放器适配；故障必须可观测、可重试、不能通过清空数据“恢复”。保存成功与内存更新明确区分。

**Non-Goals:** 不在 M0 移动播放器所有权、统一全部播放路由或建立队列。只增加保护进度必需的媒体请求身份检查，不预建 M1 的完整状态机。已实现文件与验证边界见 verification.md。

## Decisions

### 1. 逐条版本化文件，最近列表只做查询

推荐 `Application Support/PlaybackProgress/v1/records/<SHA256(legacyKey)>.json`，每个单集一个文件；原始 key 存入内容并与文件名核对，散列只用于安全文件名，不改变身份。备份采用对应 `.bak` 文件。存储位于下载目录之外，不引入 SwiftData／SQLite 或第三方依赖。

理由：目前只需按键查询、更新一个单集及排序最近时间。逐条文件天然隔离单条损坏，每 5 秒只改当前记录，不重写全部历史或队列。继续扩大 UserDefaults 数组无法提供可靠的写入失败反馈；单个 Codable 文件仍可能因一条损坏全量解码失败；数据库可以提供事务，但目前不值得增加迁移和集成面。启动枚举会随历史增长，先以大样本测量，不用自动淘汰解决规模问题。

| 记录字段 | 规则 |
| --- | --- |
| `schemaVersion`, `legacyKey` | 版本化解码；旧键严格等于 `episode.id + "|" + serverUrl`，不改 URL |
| `context` | 保存现有 `EpisodeItem` 和原始 serverUrl；可选媒体偏好沿用原 Codable 兼容性 |
| `positionSeconds`, `durationSeconds` | 有限非负位置；可信有限正时长可选，当前媒体优先、元数据回退 |
| `state` | `notStarted / inProgress / completed`，不从 95% 推断 |
| `lastListenedAt`, `updatedAt` | 实际推进才更新收听时间；写入时间不参与最近排序；迁移保留旧 playedAt 作为历史近似，不声称知道旧版真实推进时间 |
| `revision`, `origin` | 单键持久化修订及来源，便于重入和恢复判断；原始迁移位置可附在迁移来源字段供核对 |
| `seriesId`, `seriesTitle`, `seriesDetailURL`, `snapshotReference` | 可选；M0 不创建队列快照，不为填字段请求后端；M2 提供后保留关联，未知字段按版本兼容处理 |

新格式位置读回对账保存旧有限非负原值，实际恢复使用可信时长限制，不为夹限而丢掉迁移原始值。旧时长大于 0 且位置到终点，仅迁移时推断 completed；未知时长不推断。缺位置默认 0，关键身份／上下文不可恢复或非法数值的项隔离，不伪造新历史。

`PlaybackProgressStore` 为 `@MainActor @Observable` 门面：内存按键索引全量记录，`record(for:)` 查询不受 10 条限制，`recentRecords(limit: 10)` 按 `lastListenedAt` 降序、同时间按原键稳定排序。新记录尚无实际推进时不进入最近；已迁移记录保留旧顺序依据。`RecentPlaybackStore` 可暂作薄适配器供现有页面使用，但不再拥有写入旧键或截断长期记录的权力，不能保留两个权威数据源。

### 2. 写入失败与损坏恢复

文件 I/O 通过可注入 `ProgressPersistence` 接口在单一串行执行上下文完成；同键读改写事务不跨可重入 await，避免较早请求晚写覆盖较新记录。主 actor 负责生成按键递增修订，成功回执只有与待保存修订对应才清除 dirty 标记。保存接口区分已接受内存值和已提交磁盘值。

每次提交顺序：验证数值／key → 编码候选 → 在同目录写临时文件并读回核对 → 对现有有效主文件制作／原子更新上次有效备份 → 同卷原子替换主文件（首次写使用原子创建）→ 返回已提交修订。不得先删主文件；备份或替换失败即保留原主文件、dirty 内存和错误。不要把损坏主文件覆盖到有效备份。临时文件不参与正常枚举。

进程中断后只接纳完整且版本、key、数值合法的主文件；主文件无效则尝试该键 `.bak`，保留损坏原件用于修复。两者均无效只影响该键，不能全目录清空。未知高版本不覆写；迁移也不得因读取失败把旧记录静默覆盖该键。若需恢复该键，先隔离并保留损坏字节，经明确恢复路径写入；读取修复不伪造收听时间。不承诺同时损坏主备后仍找回全部历史。

原子替换保护进程中断和部分写入，不等于对所有硬件故障作绝对保证。实现时验证具体 Foundation 原子替换 API 在 iOS/macOS 的失败语义，读回成功才更新持久化水位；“每 5 秒落盘”以成功文件提交时间计，不以发送写请求或媒体位置差计。

失败时门面保留最新内存值并暴露非阻断状态，现有播放页／历史页通过 ViewModel 呈现“進度暫未儲存，請檢查可用空間”及重试操作；独立于阻断播放的 `errorMessage`。随后周期、动作、重新进入前台和手动重试均可重试最新 dirty 值；同一失败状态不反复弹窗，不另造无限重试定时器。App 异常退出只能恢复已提交值，未保存内存丢失是明确边界。

### 3. 最小播放器适配及保存语义

保留 `preparePlayback`、`stopPlayback`、媒体解析、本地优先和降噪回退结构；注入进度仓库和可控时间源。`reloadCurrentPlayback` 切源前先读取 `player.currentTime()` 和暂停／播放意图，再保存旧上下文，避免先读过期存储值再 stop。切到同一集另一媒体保持同键与秒数，并按目标当前可信时长限制。

在每次准备／切源建立媒体请求 token，捕获目标 key、AVPlayerItem 身份和 token；恢复 seek、tick、自然结束的提交前检查三者。移除旧观察者并不足以阻止已排队回调。M0 token 只服务于当前模型内进度保护，M1 全入口请求版本、M2 队列版本另行集成。

写入门控需区分准备、恢复完成与真实播放推进：item ready 且 seek 成功是恢复成功；seek 回调失败、旧 token 或无有效 player 均不能开门。实际推进来自未处于 seek 的有效播放中时间前进，不能把 seek 跳变、仅 `rate > 0`、构造 AVPlayer 或页面出现当作已收听。已完成重听保持原 completed，首次真实推进才写 inProgress。门控开启后的明确合法拖动到 0 可以保存；准备初始 0 永远不能覆盖旧值。

| 事件 | 采样及持久化规则 |
| --- | --- |
| 实际播放推进 | 更新内存及实际收听时间；复用周期观察并以单调时钟调度正常可写时不超过 5 秒的成功提交间隔 |
| 暂停（含原生控制、锁屏、拔耳机、中断） | 读取即时位置立即提交，保留已存在实际收听时间，不等待位置差阈值 |
| 有效拖动完成 | seek 完成且当前身份有效后立即提交实际落点；失败不写，拖动本身不更新实际收听时间 |
| 切集／切源／停止 | 先抓旧上下文和当前时间提交，再释放媒体；准备阶段保留旧值 |
| 前台／后台切换 | `PlayerView` 的 scenePhase 转交模型保存；iOS 必要时使用有限系统后台执行窗口完成已发起写入，不依赖终止回调；不借此改跨页播放所有权 |
| 有效自然结束 | 独立写 completed，未知时长使用最后有效位置；后续 stop 或 tick 不能抹掉 completed |
| 恢复失败 | 保留旧进度、停止自动提交初始时间、显示可重试恢复状态；重试仍针对相同有效目标 |

原生 `AVPlayerViewController`／macOS `VideoPlayer` 控件不能只依赖自定义按钮回调：暂停需观察有效播放状态变化，拖动需接入当前 item 时间跳变与 seek 完成信号，和程序化恢复 token 区分，再读取稳定落点。第 4.1 任务先验证这些路径；若系统控件事件覆盖不完整，在同一桥接层最小补齐，不以周期保存替代 PRD 的立即保存。M0 测试页面内换课／模拟切目标接口，不提前实现上一集、下一集按钮。

### 5. 自动化与测试注入

已新增最小 `ZenPlayerTests/` XCTest target，并关联 `ZenPlayer` scheme 的 Test action，覆盖 iOS Simulator 与 macOS。共享纯 Swift 测试数据；如 app-hosted 环境有隔离成本，仅将模型和持久化组件作为独立测试编译源，不复制实现、不引入另一工作流。已配置独立无 App host 的测试 bundle，直接编译生产模型／存储／门控源文件，测试数据目录完全隔离。

注入临时根目录、专用 `UserDefaults(suiteName:)`、可控时钟、故障文件适配器和播放器事件输入。用实际临时文件验证原子写／重启重读，用故障注入覆盖备份／替换／读回／标记失败，用事件序列验证恢复门控、完成重听、过期回调和暂停切源；不以镜像实现的测试替代行为断言。测试永不访问真实 App 数据容器。

## Risks / Trade-offs

- [旧键跨系列唯一性尚未验证] → 先核对仓库抓包与受控代表样本；碰撞时保留 legacyKey、停止歧义迁移并提出显式映射，不用集数／标题合并。
- [旧数组整体损坏无法安全逐条解码] → 保留原始字节，报告不可恢复来源；只在顶层合法数组内做逐项容错，不承诺修复任意破损 JSON。
- [长期文件增长与启动枚举成本] → 30 条正确性和更大规模基准验证；必要时后续建立可重建索引，不能以删进度优化，也不预设无证据数据库迁移。
- [旧版调用仍可能先删旧键] → 在任何历史／播放读取前从新仓库引导迁移，旧 singleton 的破坏性加载不能先执行。
- [macOS 多窗口存在独立播放器] → M0 同一存储实例串行化，单次写入原子；全局唯一会话留 M1，不能宣称 M0 解决多窗口播放竞争。
- [原生控件与后台保存覆盖不足] → XCTest 事件验证之外，必须记录 iPhone 和 macOS 真机操作证据；构建成功不足以证明。
- [音视频时间轴不一致] → 默认同秒恢复与有效时长限制；代表样本差异须记录，不能发明位置映射。

## Migration Plan

1. 新仓库初始化先读新结构并恢复有效备份，再直接读取旧 `recentPlayback.records` 原始 Data；不调用旧 `loadRecords()` 的删键路径。
2. 若存在旧来源，先将原始 Data 备份到独立迁移目录并校验字节摘要；保留原 UserDefaults 键。备份失败不写迁移完成标志，不执行破坏性迁移，可在内存提供有效旧记录供浏览／恢复并暴露未完成状态。
3. 顶层合法数组逐项解码，缺少新可选字段兼容；缺位置为 0；无效项保留索引和原始数据。重复 legacyKey 用旧 playedAt 最新的有效项，同时间按原数组最前项，记录去重数；不能合并已证实不同身份的碰撞。
4. 在同一串行存储上下文中仅填补缺失键。有效新格式、dirty 的新进度均优先；存在但损坏的新文件先走备份恢复，不将其视作可用旧值覆盖的“缺失”。用户边迁移边收听的新提交不能被后到的旧数据覆盖。
5. 对有效唯一旧键集合逐条核对：新增条目的键／位置／完成态读回相等；已有新值记为“由新值覆盖保护”，不可强求与旧位置相等；损坏项单列隔离。覆盖集合必须等于可迁移集合，再原子写源摘要、schema 版本、计数和迁移结果。存在隔离项标为“有效项迁移完成，部分来源待修复”，不宣称全部历史恢复。
6. 中断或标记失败可重入；标记只是优化，不能代替逐键幂等。旧源摘要相同且完成可跳过；来源变化（例如降级后再升级）需重新诊断，仍不覆盖新值。备份和旧键本版不自动删除。
7. 发布前用隔离数据演练升级和故障前向修复。发现持久化缺陷停发，保留新旧文件；不自动降级／双写旧 10 条存储，不承诺旧 App 读取新结构。整个旧源不可解析时不写成功标志，新记录可继续独立保存。

## Open Questions

当前无需要用户补充的产品决策。代表数据的唯一性、原生控件事件与真实设备后台提交覆盖属于实施验证项；如证据要求改变身份合同或扩大范围，报告具体冲突并单独确认，不能静默改规格。
